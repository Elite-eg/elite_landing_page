# Elite Tech: Design & Code Rules

> The rules this codebase follows. Read this before you build or change a page.
> Everything is shared: one color system, one set of components, one place for each kind of data.
> Before calling any change done, run `npm run check` (types + lint + the rule checks in §15), then `npm run build`.

**Keywords:** MUST / NEVER = hard rule (most are enforced by `npm run check:rules`).
SHOULD = default; only deviate with a stated reason.
**TBD** = not confirmed by the owner. Never invent a value for a TBD item; mark it and ask.

### 2.2 Where new things go

| You are adding | Put it in |
|---|---|
| A page | `app/[locale]/<route>/page.tsx` + its path in `ROUTES` |
| A component one page uses | `app/[locale]/<route>/components/` |
| A component 2+ pages use | `app/components/shared/` (or its family folder). Move it there as soon as a 2nd page needs it |
| Static data (keys, icons, config) | `app/[locale]/<route>/data/` |
| Text of any kind | `messages/ar.json` + `messages/en.json`, same key in both |
| A color, font size, shadow, radius, easing | `app/globals.css` + `tailwind.config.js` (see §3.6) |
| A route, external link, endpoint, company fact, cookie name | `lib/constants.ts` (cookie for language: `i18n/routing.ts`) |
| A motion preset | `lib/animations.ts` |
| A validation regex | `lib/validation.ts` |
| An HTTP call | `ApiService` + an entry in `API_ENDPOINTS` |

### 2.4 File conventions

- One component per file; file name = component name (PascalCase). Route folders are kebab-case.
- Hooks: `useSomething.ts`. Data files: `<page>Data.ts`. Schemas: `<thing>Schema.ts`.
- Keep components small and focused (roughly under 100 lines). Split by visual part (Card / List / Section / Visual / Form).
- Never import one page's `components/` from another page.

## 3. Colors (design system)

### 3.1 How colors work

- Every color is a CSS variable in `app/globals.css`, stored as RGB channels (`--primary: 24 64 104`),
  so opacity modifiers work: `bg-primary/10`, `border-white/25`.
- `tailwind.config.js` maps each variable to a class with `token("name")`.
- ALL colors below belong to the design system and stay available. Do not remove, rename or re-map a token
  without the owner's approval. Keep every value listed in this section.
- NEVER write hex, `rgb()` or arbitrary color values in components. The only exceptions are listed in §3.5.
- NEVER use Tailwind's default palettes (`gray-*`, `slate-*`, `blue-*`, other `orange-*` shades, …).
  Only the shades below exist in the design system.
- Choose by role: if a semantic name exists for the role (§3.3), use it (`text-primary` for headings, `bg-surface-alt`
  for a band). Use a palette shade (§3.2) for exact design roles that have no semantic name (e.g. `text-navy-300`
  for muted text on navy).

### 3.6 Adding or changing a color

1. Get the owner's approval (colors are part of the design system).
2. Add the RGB channels to `:root` in `app/globals.css`, with the hex in a comment.
3. Map it in `tailwind.config.js` with `token("name")`.
4. Add it to the tables above. If it is a new palette shade, also add it to `PALETTE_SHADES` in `scripts/check-rules.mjs`.

Non-color tokens (font size, shadow, max width, easing, font) MUST also be added to the `extendTailwindMerge` lists
in `lib/utils.ts`. Otherwise `cn()` misreads them (e.g. `text-caption` as a color) and drops or keeps the wrong class.

### 3.7 Color rules

- Orange is precious: one orange (`secondary`) button per view. Other actions are `primary`, `outline` or `ghost`.
- Section rhythm: white → `surface-alt` → white. A navy section or card is the page's one "bold" moment.
- On navy: titles `text-white`, body `text-white/75` or `text-content-dark`, eyebrow `tone="dark"`.
- On orange (CTA banner): titles white, body `text-white/90`, via `SectionHeading tone="brand"`.
- Orange text on white uses `text-secondary-dark` (contrast). `ink-400` text is for small supporting notes only.

## 4. Typography

Fonts load only through `next/font` in `app/[locale]/layout.tsx`. Never use `<link>` or `@import`.

| Role | Font | Class |
|---|---|---|
| Headings (h1–h4) | Alexandria | `font-heading` (applied automatically to h1–h4) |
| Body | Readex Pro | `font-sans` (default) |
| "Elite Tech" wordmark | Poppins | `font-logo` (Latin wordmark, always `dir="ltr"`) |
| Legacy alias | Readex Pro | `font-ibm` (kept; same as the body font) |

Type scale (fluid tokens; MUST be used for these roles):

| Class | Size | Use |
|---|---|---|
| `text-display` | 36 → 56px, bold | Hero h1 (one per page) |
| `text-h2` | 28 → 40px, bold | Big numbers, CTA-sized titles |
| `text-h3` | 20 → 24px, semibold | Card titles, panel titles, statement titles |
| `text-body-lg` | 18px, leading 1.8 | Hero paragraphs |
| (default) | 16px, leading 1.75 | Body |
| `text-caption` | 14px | Card descriptions, labels, summary rows |
| `text-xs` | 12px | Form labels, helper notes |

- Section titles MUST go through `SectionHeading`; it owns the h2 size (30 → 36 → 44px, or 24 → 32px with `size="compact"`) and spacing.
- Use `text-balance` on headings and `max-w-prose` (68ch) on paragraphs to keep lines under about 80 characters.
- Arabic needs generous line height. Never tighten leading below the tokens.

## 5. Layout, radius, shadow, z-index

### 5.1 Layout
- Page width: `Container` (`max-w-container` = 80rem, padding `px-4 sm:px-6 lg:px-8`). Narrower via `className`
  (e.g. `max-w-5xl`); this works because `cn()` knows `max-w-container`.
- `html` reserves the scrollbar gutter (`scrollbar-gutter: stable` in globals.css), so a dialog's scroll lock doesn't shift
  fixed elements (header, WhatsApp button); while a dialog is open the gutter is tinted like the dimmed page.
- Sections: `py-20 sm:py-24` by default. `<main>` already offsets the fixed header (`pt-16 sm:pt-20 lg:pt-28`);
  anchors get `scroll-padding-top: 7rem`.
- Split heroes: copy `lg:col-span-7`, visual `lg:col-span-5`. Copy comes first in the DOM, so it sits on the start
  side (right in Arabic).

### 5.2 Radius (by hierarchy, not one radius for everything)

| Element | Radius |
|---|---|
| Hero tiles, CTA banner | `rounded-[2rem]` |
| Large feature cards (statements), modals | `rounded-3xl` |
| Cards, panels, forms, summary | `rounded-2xl` |
| Inputs, buttons (md/lg), icon tiles, list rows | `rounded-xl` |
| Small icon tiles, sm buttons | `rounded-lg` |
| Pills, eyebrows, step circles | `rounded-full` |

### 5.3 Shadows (tinted with the tokens)

| Class | Use |
|---|---|
| `shadow-card` | Default light card |
| `shadow-card-hover` | Hovered light card (same layers as `shadow-card`, larger). Use through `CARD_HOVER_CLASSES` (§9.1), not by hand |
| `shadow-lift` | Dark / hero tiles, modals, menus |
| `shadow-widget` | Floating widgets on navy (booking widget, phone mockups) |
| `shadow-glow` | Orange CTA |
| `shadow-glow-accent` | Accent glow |

Don't stack shadows under everything. Light cards SHOULD use `border border-edge` + `shadow-card` at most.

### 5.4 Z-index scale

| Layer | Value |
|---|---|
| Local stacking inside a component | `z-0`, `z-10`, `-z-10` (+ `isolate` on the parent) |
| Floating WhatsApp button | `z-50` |
| Fixed header | `z-[100]` |
| Mega menu panel | `z-[110]` |
| Mobile drawer | `z-[120]` |
| Modals (Headless UI Dialog) and anchored menus | `z-[130]` (MUST be above the header, so the backdrop dims it) |
| Toasts | react-hot-toast default (above everything) |

### 5.5 Imagery
- Logos: `/images/logo.png` (light backgrounds), `/images/logo-light.png` (navy backgrounds), `/images/logo-square.jpeg`.
- Prefer brand visuals built in code (navy gradient tile + logo + `bg-dot-grid-light` + soft `secondary`/`accent`
  blur glows) over generated images. Examples: `AboutHeroVisual`, `GuideCover`.
- Every image uses `next/image` with `width`/`height` or `fill` + `sizes`. Decorative images get `alt=""` and their
  wrapper gets `aria-hidden`. Meaningful images get a localized alt (from messages).
- `priority` only for images above the fold (the header logo, hero images). `Logo` takes a `priority` prop for this.
- Background utilities: `bg-dot-grid` (navy dots, light sections), `bg-dot-grid-light` (white dots, navy surfaces).
  Fade them with `[mask-image:linear-gradient(to_bottom,black,transparent)]`.

### 5.6 Design principles
- Build from the brand and the real content. Avoid the generic SaaS look (gradient washes everywhere, identical floating cards).
- Spend boldness in ONE place per page (hero visual or one navy card). Keep the rest quiet.
- Eyebrows only where they help orient the reader (hero, product sections). Not above every heading.
- Number markers (01, 02 / 1, 2, 3) only for real sequences or ranked lists. Check marks for plain lists.
- No "→" on every button. Arrow icons for forward navigation only, flipped in RTL.

## 6. Motion

Presets live in `lib/animations.ts`. Components import them and MUST NOT define their own variants inline.

| Preset | Use |
|---|---|
| `heroStagger` + `heroTextReveal` + `fadeInUp` | The hero copy (eyebrow → h1 → paragraph → extras) |
| `withDelay(slideInFromEnd(isRtl), 0.45)` | The hero visual, after the copy |
| `floatLoop`, `floatLoopOffset` | Gentle loops on hero visuals (easeInOut) |
| `fadeInUp`, `fadeIn`, `scaleIn`, `imageReveal`, `slideInLeft/Right` | Reveals (through `<Reveal preset>`) |
| `slideInFromStart/End(isRtl)` | Horizontal slides that mirror in RTL (also `<Reveal preset="slideInFromStart/End">`) |
| `staggerContainer` | Grids (through `<RevealGroup>`) |
| `listItemFromEnd(isRtl)` + `custom={index}`, `listSwap`, `heightTransition` | Filterable lists (jobs openings): rows slide in from the end side one after another; a filter change fades the list out (`AnimatePresence mode="wait"`), brings the new rows in from the top, and `AnimatedHeight` lets the content below glide to its new place |
| `layoutTransition` | Selection indicators gliding between options (`layoutId`), e.g. the jobs department pills |
| `popIn` | Result icons, floating dots |
| `checkPop` | Check marks in choice controls (`ChoiceChips`, `CheckboxField`): pop in with a slight overshoot, leave quickly; inside `<AnimatePresence>` |
| `fillIn` | A selection indicator appearing where nothing was selected (first `ChoiceChips` answer); afterwards it glides with `layoutTransition` |
| `growY`, `growYFromTop`, `drawPath` | Chart bars, timeline connectors, line drawing |
| `botEnter` | Maher bot entrance |
| `withDelay(preset, s)`, `viewportOnce`, `MOTION` | Helpers and timings (mirror the `--motion-*` CSS tokens) |

CSS equivalents in `globals.css`: `animate-hero-rise`, `.reveal` + `.is-visible`, `animate-draw`, `animate-draw-dot`,
`animate-pop`, `animate-pop-float`, `animate-grow-y`, `.bot-dock`; in Tailwind: `animate-marquee`, `animate-accordion-down/up`.

Rules:
- One orchestrated hero moment per page. Below the hero, reveal with `<Reveal>` (single blocks) and
  `<RevealGroup>` + `<Reveal inGroup>` (staggered grids). They trigger once.
- Hover states change color, border or shadow only (e.g. icon tile turns navy). Every light content card takes
  `CARD_HOVER_CLASSES` (rests on `shadow-card`, grows to `shadow-card-hover`, 300ms) plus its own hover border. No lift on cards;
  only buttons lift (built in). Form choice controls animate their state change: dropdown lists drop in (200ms ease-out) and
  close faster (150ms ease-in), chips and checkboxes fade their fill and pop their check.
- Animate `transform` and `opacity` only. Two exceptions, both height on a single container: `jobs/components/AnimatedHeight`
  (the note and footer follow a filtered list; transforms can't move content outside the component) and accordion-style
  expand / collapse with `expandCollapse` + `expandTransition` (the requirements in the jobs apply modal). Height isn't
  covered by `MotionConfig`, so both pass `{ duration: 0 }` when `useReducedMotion()` is true.
- Reduced motion: Framer Motion is handled by `MotionConfig reducedMotion="user"`; the CSS utilities by the
  `prefers-reduced-motion` block. Tailwind's looping animations (`animate-pulse`, `-ping`, `-bounce`) MUST be written
  `motion-safe:animate-*`. A loading spinner (`animate-spin`) is allowed.
- Every `animate-*` class must exist (Tailwind default, tailwind.config.js or globals.css); a typo silently does nothing.
- A motion element inside an `<AnimatePresence initial={false}>` (e.g. a form swapped for its success panel) never plays its
  `initial` animation, even when it mounts later. Give late-mounting elements their own `<AnimatePresence>` (see `ChoiceChips`).
- `layout` elements re-animate on any re-render that moves them; pass `layoutDependency` so they only animate when their own
  state changes (otherwise they slide in late when, say, error lines push the form down).
- Step changes in multi-step flows: re-key a `motion.div` with `fadeInUp` (and scroll to top for full-page steps).

## 7. RTL & internationalization

- ALL user-facing text lives in `messages/ar.json` and `messages/en.json`, with the same keys and the same
  `{arguments}` in both. Never hardcode text (Arabic or English) in a component, including toasts, Zod messages,
  WhatsApp messages and placeholders.
- Namespace per page/feature: `home`, `about`, `jobs`, `booking`, `guides.<key>`, `checkout`, `caseStudies`,
  `joinTeamCta`, `validation`, `site`, `nav`, `footer`, `notFound`, …
- ICU params for dynamic values (`{brand}`, `{email}`, `{amount}`, `{count}`), ICU `plural` for counts
  (e.g. `jobs.badge`), ICU `select` for per-country variants (`{country, select, SA {…} other {…}}`).
- Rich text: `t.rich("key", { br: () => <br /> })` with `<br></br>` in the message. Languages may differ in tags.
- Use logical utilities only: `ms/me`, `ps/pe`, `start/end`, `text-start/end`, `border-s/e`, `rounded-s/e`.
  NEVER `ml/mr/pl/pr/left/right/text-left/text-right` for layout.
- Directional icons flip with `rtl:-scale-x-100`, or `flipIconInRtl` on `Button`.
- LTR data inside Arabic UI (phones, emails, links, IBANs, card numbers, order numbers, the wordmark) uses `dir="ltr"`.
  LTR inputs without an icon add `inputClassName="rtl:text-end"` so text lines up with the label.
- Build quirk: Turbopack compiles logical utilities into physical `left`/`right` rules keyed on the element's
  **language** (`:lang(ar)`), not on `dir`. A nested `dir="ltr"` block on an Arabic page still maps `ps-*` /
  `start-*` to the right. Use `dir` for text direction; don't expect it to flip spacing. `InputField` handles
  icon + `dir` for you.
- Numbers, money and dates: `new Intl.NumberFormat(intlLocale(locale), …)` / `Intl.DateTimeFormat(intlLocale(locale), …)`,
  so digits are Latin in both locales and the server and the browser render the same string.
- "Today" on the server: compute it in `APP_TIME_ZONE` (see `book-session/utils/bookingDates.ts`). Never use the
  server's or the browser's local zone for rendered dates; they differ and break hydration.
- Internal links go through `@/i18n/navigation` (or `Button href`), never `next/link` or `next/navigation` hooks directly.
- The language toggle (`useLocaleToggle`) stores the choice in `LOCALE_COOKIE`; `middleware.ts` uses it for unprefixed URLs.
- Editing messages: merge with a small Node script (`JSON.stringify(obj, null, 2)` + newline) to keep formatting identical,
  then check `git diff --stat` shows only the intended keys.

## 8. Clean code

- Server components by default. Add `"use client"` only for state, effects, browser APIs or Framer Motion, and push it
  as low as possible (sections stay server components; `Reveal` handles motion).
- Props typed with an explicit `interface`. No `any`. No unused props ("just in case" props get removed).
- Variant styling uses a typed lookup map (`Record<Variant, string>`) + `cn()`. No class string concatenation.
- Merge classes with `cn()` from `lib/utils.ts` (it knows the custom tokens; see §3.6).
- Icons: `react-icons/fi` (Feather) everywhere; `react-icons/fa6` for brand marks (WhatsApp, Apple). Icons are
  `aria-hidden`; icon-only controls need an `aria-label`.
- No `console.*`. Use `log` from `app/services/logger` (ApiService logs in development only, never headers).
- Data files hold keys, icons and config, not copy: `ALBIRUNI_FEATURES = [{ key, icon }]` → `t(\`features.${key}.title\`)`.
- Template pages: when several pages share a layout, build one template driven by a key + config
  (`GuideLanding guide="eInvoicing"`). Each route file is then about 15 lines.

## 10. Forms & submissions

- React Hook Form + Zod + `zodResolver`. The schema is the single source of validation; forms use `noValidate`.
- Zod messages are KEYS in the `validation` namespace (`"phoneInvalid"`), shown with `useTranslations("validation")`.
- Shared regexes live in `lib/validation.ts` (`PATTERNS.phone`, `mobile.EG` / `mobile.SA`, `mobilePrefix.EG` / `.SA`, `cardNumber`,
  `cardExpiry`, `cardCvc`). Mobile numbers have no leading 0 after the dial code: EG `^1[0125]\d{8}$` (10 / 11 / 12 / 15),
  SA `^5[013-9]\d{7}$`. Typing a 0 first is an error; pasting drops it ("01122999933" → "11 2299 9933").
- Conditional rules use `superRefine` (e.g. card fields only when `method === "card"`).
- Every input has a visible label, an error state, the right `autoComplete`/`inputMode`, and is disabled while
  submitting (`disabled={isSubmitting}`). Submit buttons use `isLoading`.
- Multi-step forms keep typed values when the visitor goes back (see `book-session/components/DetailsStep.tsx`).
- Choice controls (country toggle, payment methods, meeting types, filters) use Headless UI `RadioGroup`/`Radio`
  (questions inside a form: `ChoiceChips`).
  Never put inputs inside a `Radio`; render them as a sibling block under the selected option.
- HTTP goes through `ApiService` only, to an endpoint in `API_ENDPOINTS`. Show success ONLY when the response is 2xx.
  NEVER fake a success with a timeout or a local state change: while an endpoint is TBD the visitor sees the error
  toast (which offers WhatsApp as the alternative). Exceptions, each marked in code: draft prototypes (`/draft`) and
  the booking widget until its endpoint exists (TODO in `BookingWidget.tsx`).
- Feedback: React Hot Toast. Success says what happened ("We sent the guide to your WhatsApp"). Errors say what failed
  and what to do ("Check your connection and try again"); never apologize, never stay vague.
- Modals: Headless UI `Dialog` at `z-[130]`, a close button with `aria-label`, Escape closes, focus is trapped.

## 11. Copy & voice

- Arabic: Modern Standard Arabic, simple and direct. Existing style uses tanween on alif (مجاناً، يوماً).
- English: sentence case, plain verbs, no filler.
- CTAs name the outcome: "أرسل لي الدليل مجاناً", "متابعة إلى الدفع", "شاهد الوظائف المتاحة". Never "Submit"/"Click here".
- An action keeps one name through the flow (button "Send me the guide" → toast "We sent the guide…"), and a button
  does what its label says ("Back to home" goes home).
- Counts come from data, never typed into copy (`jobs.badge` uses `{count}` = number of openings).
- Don't invent facts, prices, stats, client names, social handles or legal claims. Sample data goes in `data/` under a
  `SAMPLE_` name with a `DRAFT SAMPLE / TBD` comment, and is listed in the task report.

## 12. Accessibility checklist

- One `h1` per page. Flows without a hero use a visually hidden `<h1 className="sr-only">` (draft checkout).
- Sections use `h2` via `SectionHeading`, cards `h3`. Unlabeled `<section>`s without a heading get `aria-label`.
- Landmarks: `nav` for menus and steppers, `aside` for summaries, `article` for cards, `dl` for label/value data.
- Icon-only buttons: `aria-label`. Decorative icons and images: `aria-hidden` / `alt=""`.
- Repeated buttons ("Apply now" ×10) get `aria-describedby` pointing at their card title.
- Calendar days carry the full date as `aria-label`; toggles expose state (`aria-pressed`, radio `aria-checked`).
- Keyboard: Headless UI handles menus, dialogs and radio groups; the global `:focus-visible` ring must stay visible.

## 13. Pages & SEO

- Every page exports `generateMetadata` and returns
  `buildPageMetadata({ locale, path: ROUTES.x, title, description, type?, noIndex? })`.
  It sets the title, description, canonical + hreflang (incl. `x-default`), Open Graph (with the shared image) and
  Twitter tags. NEVER hand-write `openGraph`, `twitter` or `alternates`: Next.js replaces (does not merge) a parent's
  objects, so the page silently loses the image and URL.
- Titles: the root layout already appends `| {brand}`. Page titles MUST NOT include the brand. Descriptions may use `{brand}`.
- Draft pages pass `noIndex: true`. The 404 page sets its own title and `noindex` in `not-found.tsx`.
- Site-wide defaults (title, description, keywords, icons, robots) live in the root layout + `site` messages.

## 15. Verification workflow

1. Plan: list the sections, components, data shape and message keys before coding.
2. Build: tokens → shared components → page sections → messages (ar + en together).
3. `npm run check` MUST pass. It runs `tsc --noEmit`, `eslint` and `scripts/check-rules.mjs`, which enforces:
   - messages: same keys in ar/en, valid ICU syntax, same `{arguments}`; every literal `t("key")` exists
   - colors: no hex (except §3.5), no Tailwind default palettes, only palette shades that exist
   - RTL: no physical direction utilities; i18n: no `next/link` / `next/navigation` hooks, no Arabic copy in components
   - routes from `ROUTES` (no `href="/…"` literals), no `console.*`, no `any`
   - motion: `motion-safe:` on looping Tailwind animations, no undefined `animate-*` classes
4. `npm run build` MUST finish with zero warnings.
5. Smoke test: start the build (`npx next start`) and `curl` each route in both locales: HTTP 200, correct `<title>`
   (brand once), one `<h1>`, correct canonical / `og:url` / `og:image`, no raw message keys.
6. Browser: `/ar` and `/en` at 360 / 768 / 1280 px: no horizontal overflow, no console errors. Exercise every form
   (empty submit → localized errors; valid submit → request sent), modals (Escape, close label, above the header),
   the mobile drawer, mega menus (inside the viewport) and the language toggle.
7. Report: files changed, assumptions, sample/TBD data, and anything not verified.
